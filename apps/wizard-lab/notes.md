# Wizard Lab — notes

## log
- v1.0 (2026-09-19): built per two chat requests read as ONE app ("compact cozy wizard-lab puzzle app with grid logic first, escalating levels, reset controls, progress tracking" + "wizard potion lab decorator with emerald cauldron glow, dragon tears, bottled storm interaction, familiar selection"). GRID LOGIC (pure `<script id="eng">`, dual-exported): an n×n board of rune states 0..k−1; tapping a cell adds 1 (mod k) to its whole row and column (the crossing cell once); the board starts calm and is scrambled with seeded taps, so every level is solvable; `need[]` tracks the taps each cell still wants (taps commute), which gives par, hints, remaining count and progress. Levels escalate: size 3→6 (one step every 3 levels), rune states 2→4 (every 4 levels), scrambles = level + 2 (cap 36), 30 levels. Controls: tap/Enter on a cell, U undo (counted as a stir), R reset (same seed, same runes), N next when calm; keyboard T/S for the jars. DECOR: the cauldron's emerald glow is driven by a `--glow` custom property = calm rows / rows (1 when solved) — pot halo, surface, bubbles all read it; a flickering flame; dragon tears = 2 hint uses per level (3 with the cat) that mark a rune that truly needs stirring and say how many times; the bottled storm uncorks 3 wild scramble taps (2 with the toad) with a lab shake + lightning sweep; familiars (cat / owl / toad) are a persisted choice with one mechanical effect each and a flavour line. PROGRESS: `wizard-lab-v1` = {level, best per level, familiar, solvedLevels, seed}; verdicts by stirs over par. On phones a 6×6 grid of 44 px runes cannot fit 320 px, so the grid scrolls INSIDE its card (the page never scrolls sideways) — needed `minmax(0,1fr)` on the stacked column (the 1fr = minmax(auto,1fr) trap again). Uncial Antiqua + Averia Serif Libre, plum/stone/emerald/amber. Tests: eng 24/24 (escalation table, tap/undo semantics, levels 1–30 × 4 seeds solved by hints in exactly par stirs, seeding, progress/verdicts, tears/storm/familiars, solved-lock), probe 26/26 ×3 widths (grid, HUD, stir + undo, tears mark, storm flash, solve → glow 1 + next focused, best saved, N/R keys, escalation to 6×6 with ≥44 px cells, familiars persist + effects, a11y), screenshots 1200/390.

## issues
- A 6×6 grid at 44 px per rune is 252 px wide at minimum; on a 320 px phone it scrolls within the card by design (targets stay 44 px). If chat wants no scrolling, the honest trade is 40 px runes at that width.
- A dense-grid probe passed at 390 and failed at 1200 once with identical code (focus-timing on the "next" button); the check now records diagnostics — if it recurs, it is the focus call, not the puzzle.

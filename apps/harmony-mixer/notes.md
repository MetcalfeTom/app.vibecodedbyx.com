- 2026-08-29 v1.2 — **beat grid + beat sync + persistent hot cues + deck restore** per a public request ("add local audio file loading and persistent cue points to Harmony, prioritizing reliable beat matching"). Local loading already existed (v1.0); this makes it persistent and adds the beat layer.
  - **Beat grid** (`beatGrid(env, bpm, x, sr)` in the DSP block, computed in the worker next to bpm/key): `onsetEnvelope` now returns `{on, low, fr}` — `on` = full-band log-flux (v1.0's), `low` = LINEAR-magnitude flux below 160 Hz. The grid is fitted to `on/mean + 3·sigLow·low/lmean` (sigLow = how sparse the kick band is; a tone's leakage isn't) — because log flux lets a broadband hat burst outscore a kick, and a grid fitted to raw `on` locked onto the HATS of a synthetic track. Steps: phase comb at the autocorr tempo → 3 rounds of weighted least squares (each expected beat ↔ strongest peak within ±20 % of the period, weight = height/distance) → candidate tempo multiples ½, 2, ⅔, 3/2 scored by (kick-weighted grid strength × peak energy explained × 120-prior, autocorr pick ×1.15) → FINE PHASE: 2.9 ms energy-rise envelope of the waveform comb-searched −40…+120 ms (STFT frames peak ~70 ms BEFORE the attack — v1.0's frame time is the window start) → downbeat = the 4-slot with most energy → `conf = min(matched share, (grid/mean ratio − 1.1)/1.4, (top-decile/mean − 2)/2)`; `< .25` → no grid. Result `{bpm, beat0, downbeat, conf}`; `analyseTrack` returns `bpm` = grid bpm when a grid exists. Node suite (`grid-test.js`): 6 synthetic tracks 87.5–140 BPM incl. an accented bar, a 3.2 s silent intro, noise, and a coarse ⅔-tempo miss → bpm within 0.01, phase within 1.3 ms, downbeats right; helpers; pad/silence/short → null or conf ≤ .54.
  - **Beat sync** (`#sync`, key S): sets tempo lock, `alignTo` snaps the follower the shortest way onto the master's beat phase (`alignDelta`, ≤ ½ beat; a seek while playing, just the start point while paused — `play()` re-aligns a synced follower on start), then `syncTick()` every frame: phase error over 0.06 beat → snap again (somebody jumped), under → proportional bend `1 + 0.3·e` clamped ±1.5 % (`setBend`, a multiplier on top of the pitch fader: `prate() = rate × bend`, used by pos/play/setRate; the BPM readout ignores it), deadband 0.002 beat, guarded to same-length beats (±3 %) so a hand-edited crate BPM can't make it hunt. Unlock ends sync; master swap re-aligns. Per-deck **nudge** ◂ ▸ (hold, ±4 %; keys Q/W and O/P) overrides the loop while held. Centre **phase strip** (`#phasecv`, ±2 beats per deck around a fixed playhead, bar ticks taller) + `#drift` text ("in phase" < 5 ms, else "B behind 12 ms", "no beat grid on B").
  - **Hot cues**: 4 pads per deck (keys 1–4 / 7–0; click sets or jumps, shift-click / right-click / 650 ms hold clears), `snap` toggle rounds new cues to the nearest grid beat, cue flags + bar lines drawn on the waveform (`drawMarks`). **Persistence**: `fingerprint(chan0, sr)` = sample count + 128 RMS segments (6-bit) double-FNV → 16 hex; `localStorage['harmony-mixer:tracks:v1'][fp] = {v:2, name, bpm, key, grid, cues[4], seen}` (300 most recent) — cues survive renames and a reload, and a fingerprinted track skips the worker entirely (`cached`). IndexedDB `harmony-mixer` / store `decks` keeps the last file's bytes per deck (`loadBytes(bytes, name, fromStore)`, the ArrayBuffer is copied BEFORE decodeAudioData detaches it) → both decks come back on reload with cues + analysis in ~150 ms. Separate from the crate's `harmony-crate-v1` DB.

- 2026-08-28 v1.0 — first build per a public request: "Harmony's minimal two-deck mixer with Camelot colors, chord names, BPM displays, tempo lock, local audio, and crossfader".
  - Two Web Audio decks (AudioBufferSource → Analyser → level gain → crossfader gain → master). Pause = stop + remembered offset; `pos()` = posAtStart + (ctx.currentTime − tStart) × rate, snapshotted on every rate change so pitch moves never jump the playhead.
  - Analysis runs in a Blob worker built from `<script id="dsp">` (also evaluable in node — see harness). BPM = spectral-flux onset strength (STFT 1024/128 at ~11 kHz) → autocorrelation, score = Σ ac(k·lag)/k for k=1..4 × log-normal prior around 120, refined with parabolic peaks at lag multiples (±0.1 BPM on synthetic material). Key = peak-picked chromagram (8192 FFT, 180 s from 8 % in) → Krumhansl profiles → Camelot via `camelotOf`. Live chord = analyser spectrum → chroma (EMA .72) → best major/minor triad (cosine ≥ .62, 3 consecutive votes).
  - Camelot colours: hue = 170 − (n−1)·30, A pastel / B saturated; each deck's `--dk` var tints its letter, badge, waveform, play button and the crossfader track ends. Centre wheel = 24 SVG arcs; lit segments are the loaded keys; compat text (same / relative / neighbours / diagonal / two steps / clash).
  - Tempo lock: follower rate = master effective BPM / follower BPM, re-applied on the master's pitch input; follower fader disabled; A→B / B→A swap chip. Crossfader is equal-power (cos/sin), sticky at the bottom, ← → keys nudge it; Space / Enter play A / B.

## issues
- Beat grid is ONE constant tempo per track (like every DJ beatgrid): live drummers / tempo ramps get a "loose grid" label (conf < .6) and sync will re-snap every time the drift passes 0.06 beat. No warp markers.
- Beat sync aligns BEATS, not bars — the downbeat detector is a heuristic (loudest 4-slot), so a bar-level sync would sometimes jump two beats the wrong way; the phase strip shows both decks' bar ticks so the DJ can nudge a bar by hand.
- conf thresholds (grid null < .25, "loose" < .6) were tuned on synthetic material only — dense real mixes have a lower grid/mean ratio; if real tracks all read "loose grid", relax `(ratio − 1.1)/1.4` first.
- Crate-loaded tracks get the crate's stored bpm via `applyMeta` (coarse detectBPM or a hand edit) while `d.grid.bpm` is the fitted one; tempo lock uses `d.bpm`, the sync loop measures phase with the grid and bends up to 1.5 % to cover the difference; if the two disagree by > 3 % the loop stands down (guard in `syncTick`).
- The deck-restore store keeps the file bytes a second time next to the crate's blob (two IndexedDB databases); harmless, but a shared store would halve the space.
- Crate: `.next{display:grid}` / `.btn{display:inline-flex}` silently beat the `hidden` attribute — the empty crate showed a phantom "NEXT UP → B" strip while the probe's `.hidden` property check passed. Fixed with `#crate [hidden]{display:none!important}`; probes now assert `getComputedStyle(...).display`, not the property.
- Crate: `added` stamps must be unique — 4 files imported in one `importFiles` call shared a millisecond and "newest first" tied (fixed with a monotonic `stamp()`).
- Crate: loading from the crate still re-runs the deck's own analysis (setBuffer's contract) — harmless (~1.6 s/30 s in a worker) but a `meta` argument on setBuffer would skip it.
- Crate: "next for · auto" follows the LAST LOADED deck when nothing is playing, so right after loading the suggestion into B the reference flips to B — intended (B is what you'll play next), but it surprises a probe that expects A.
- Key detection on very sparse synthetic material can land on a neighbour (a D-major triad + 70 Hz kick read as F♯ minor); the crate stores whatever the deck/worker said and lets you ✎ fix it.
- Pitch is plain resampling (playbackRate), so ±8 % shifts the key ≈ ±1.3 semitones — deliberate vinyl feel; the key badge shows the analysed (0 %) key.
- Key confidence < .25 shows a "?" after the key name. Sparse / drone-y material and DnB half-time will occasionally read an octave/relative off.
- Analysis takes ~1.6 s per 30 s of audio in the worker (≈ 15 s for a 5-minute track); the wave shows "reading bpm + key…" meanwhile and the deck already plays.
- Headless testing: an `await` on a worker with no pending timers makes `--virtual-time-budget` jump to its deadline before the worker replies — use the real-time hold/release harness (pending `<img src=/_t/hold>` blocks `load`; the tail fetches `/_t/release` when done) in the job tmp.

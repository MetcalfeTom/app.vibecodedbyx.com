- **LOOP REDESIGN MAP — 2026-09-08** (chat: "map 1/64→32 bars, grid-lock toggle, forward/reverse, preserve current behavior, propose safe tests" — MAP ONLY, nothing built). Grounded in the shipped loop (setLoop beat-snaps loopA, loopTick live-seeks the wrap each frame, media-element engine, forward-only).
  **1) Lengths 1/64→32 bars** (12 halving steps): replace the 4-option select with ÷2/×2 buttons flanking an aria-live readout inside ONE .selgrp wrapper (v3.2.1 lesson). Snap unit: ≥1 bar keeps beat-snap (current behaviour preserved verbatim); <1 bar snaps loopA to the loop-length lattice off beat0 (metric micro-loops). HARD CONSTRAINT mapped: at 128bpm a 1/64 bar is 29ms but loopTick wraps at frame granularity (~17ms jitter = audible chaos) and media seeks under ~20ms are swallowed (proven in the v3.2.3 work) — so loops ≤1/8 bar must swap that deck onto the BUFFER engine with native AudioBufferSourceNode.loop + loopStart/End (sample-accurate, zero seeks), returning to the media path on release. Cost: buffer path has no preservesPitch — keylock chip should show a 'vinyl (loop)' state while engaged.
  **2) Grid-lock toggle** (default ON = today's snap, preserved): OFF = loopA at the exact engage position, lengths still musical. Consequence mapped honestly: unsnapped wraps perturb sync phase every cycle and the PLL will fight them — show the amber warn on the loop chip when OFF+synced, block nothing.
  **3) Forward/reverse/ping-pong**: HTMLMediaElement CANNOT play backwards (no negative playbackRate in Chromium) — reverse forces the buffer engine playing a REVERSED COPY of the loop segment (built once per engage; 8 bars ≈ 10MB floats fine, 32 bars ≈ 40MB → build async w/ status, free on release). Ping-pong alternates segment/reversed per pass. Sync in reverse is meaningless: PLL freezes bend at 1 while loopDir ≠ fwd, drift reads 'reverse loop', SYNCST stays engaged for the return.
  **4) Preservation invariants**: defaults unchanged (4 bars, forward, grid-lock ON); the EXISTING loop-tail 20 + hd 18 + cont 12 + sync 32 + proll/phrase/voc suites must pass UNMODIFIED — any old-suite edit is a declared behaviour break.
  **5) Proposed safe tests (write BEFORE code)**: (a) pure length-map: 12 exact steps, ÷2/×2 end-clamps, readout strings; (b) engine swap: 1/16-bar engage → d.loopEngine==='buffer', seek-spy counts ZERO wraps, release returns to media ±30ms w/ keylock restored; (c) micro-loop period: pos-mod-len sawtooth period exact on the buffer path (fake clocks for decisions, per v3.2.3 lessons); (d) grid-lock ON lattice assert w/ WRAPPED fraction (min(f,1−f)), OFF exact-position, warn class when OFF+synced; (e) reverse: pos decreases monotonically inside [A,B], reversed buffer's head samples equal the original tail (content assert), ping-pong Δpos sign flips once per period; (f) sync stand-down in reverse + clean restore; (g) the preservation battery verbatim; (h) 32-bar reverse memory: async build w/ status, buffers freed on release (seam null check); (i) new controls at 1200/390/320 (selgrp + grid-column lessons). Risks: edge clicks on buffer loops (optional 5ms micro-fade), pitch shift during buffer loops at rate≠1 (document, don't hide).

## issues
- Crate: `pump()`'s drain branch used to `status('')` unconditionally — any message set while the queue was idle (dup skipped, adoption) was wiped the same tick it appeared, because importFiles always ends with `pump()`. Now it only clears when the current status carries the `busy` class. Lesson: a cleanup that resets shared UI state must check it still owns that state.
- Crate: `<option>` text collapses whitespace — playlist tree indentation uses figure spaces ( ), not plain spaces.
- Crate: `.next{display:grid}` / `.btn{display:inline-flex}` silently beat the `hidden` attribute — the empty crate showed a phantom "NEXT UP → B" strip while the probe's `.hidden` property check passed. Fixed with `#crate [hidden]{display:none!important}`; probes now assert `getComputedStyle(...).display`, not the property.
- Crate: `added` stamps must be unique — 4 files imported in one `importFiles` call shared a millisecond and "newest first" tied (fixed with a monotonic `stamp()`).
- Crate: loading from the crate still re-runs the deck's own analysis (setBuffer's contract) — harmless (~1.6 s/30 s in a worker) but a `meta` argument on setBuffer would skip it.
- Crate: "next for · auto" follows the LAST LOADED deck when nothing is playing, so right after loading the suggestion into B the reference flips to B — intended (B is what you'll play next), but it surprises a probe that expects A.
- Key detection on very sparse synthetic material can land on a neighbour (a D-major triad + 70 Hz kick read as F♯ minor); the crate stores whatever the deck/worker said and lets you ✎ fix it.
- Pitch is plain resampling (playbackRate), so ±8 % shifts the key ≈ ±1.3 semitones — deliberate vinyl feel; the key badge shows the analysed (0 %) key.
- Key confidence < .25 shows a "?" after the key name. Sparse / drone-y material and DnB half-time will occasionally read an octave/relative off.
- Analysis takes ~1.6 s per 30 s of audio in the worker (≈ 15 s for a 5-minute track); the wave shows "reading bpm + key…" meanwhile and the deck already plays.
- Headless testing: an `await` on a worker with no pending timers makes `--virtual-time-budget` jump to its deadline before the worker replies — use the real-time hold/release harness (pending `<img src=/_t/hold>` blocks `load`; the tail fetches `/_t/release` when done) in the job tmp.

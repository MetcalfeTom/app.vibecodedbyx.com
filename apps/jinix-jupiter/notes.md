# Jinix Jupiter — fantasy console + one cart

## log
- 2026-08-28: v1.0 — built per a public request ("small vanilla JS canvas fantasy-console prototype inspired by Jinix Jupiter, keyboard controls, pixel-art visuals, one playable level"). Interpreted "Jinix Jupiter" as the console name + cart name, since no such product is documented. CONSOLE (JX-192): 192×128 software framebuffer (`Uint8Array` palette indices → `Uint32Array` ABGR → 192×128 offscreen canvas → nearest-neighbour `drawImage` onto a dpr-sized display canvas; integer CSS scale ≥2 on desktop, fractional fill on phones), 16-colour Jupiter palette, API `cls/pset/rectfill/spr/print/printc/camera/btn/btnp/sfx`, sprites as 8 hex-digit rows ('.' transparent), 3×5 bitmap font (A-Z 0-9 .:!-/,?>×♥·'()), tiny Web Audio synth (jump/gem/stomp/death/flag/win/start/boot), sound off by default (persisted `jinix-jupiter-sound`). CART (JUPITER): 108×16 ASCII map (`#` ground autotiled top/fill, `-` one-way band w/ surface at tile-top+2, `^` spike, `o` gem ×8, `w` wisp ×5, `F` checkpoint ×2, `c` cloud deco, `P`, `E` pod). Physics per 60Hz frame: ACC .18 / MAX 1.15 / friction .82 / G .22 / JV −3.5 (≈26px rise; 3-tile band climbs need ≥24) / max fall 4, coyote 6f, jump buffer 6f, variable height (release → vy clamped to −1.2). Edge sampling uses `ceil(x+w)-1` (floor(x+w-1) caused sub-pixel wall jitter 66→66.9→66). Wisps patrol 0.45px/f, turn at walls/ledges/spikes, stompable (bounce −2.4), else lethal. Death → 50f fall anim → respawn at last flag, wisps reset, gems kept. Exit → clear panel (time, gems, deaths, PERFECT RUN if 8/8 + 0). Boot screen (90f) → title (parallax bands, blinking prompt) → after 12s idle an ATTRACT DEMO plays: `DEMO_RLE` is a machine-found perfect run (885 frames, wisps hidden = "ghost run"); any real button aborts. Chrome: cream handheld shell (Handjet + Chivo Mono), d-pad ◀▶ + A/B (both jump) as real pointer/keyboard buttons, sound + reset pills, aria-live status line, buildstamp. Probes: desktop 29/29 (boot/title/launch, wall stop at 66.00, jump apex + landing on the step, gem pickup, spike death + respawn, wisp stomp, one-way band land + jump-through, checkpoint + respawn-at-flag, exit/clear, R restart, keyboard + pointer d-pad drive movement, elementFromPoint hit-tests, 576×384 integer scale, 15 palette entries painted, 44px targets, sound toggle persisted, a11y roles, no hscroll, demo bake replays to 8/8 + 0 deaths, demo abort, COMPLETABILITY search), mobile 6/6 (375px: no hscroll, 315×210 screen, controls visible + hit-test, touch A jumps 23px, deck within viewport).

## issues
- **Completability is machine-checked** (probe `completable`): a best-first search over the REAL physics (seam `__X.step/press/clearPrev/clearFx`, `noRender`), waypointed through every one-way band + gem in x-order, then the exit. It caught a real design bug: band climbs were exactly 24px apart and the jump rose 23.85px. Any physics/level change → rerun; the baked demo (`DEMO_RLE`) MUST be regenerated from the probe's `data-script` output afterwards or `demo-bake` fails (it replays the script and requires clear + 8/8 + 0 deaths).
- The search removes wisps (their positions aren't part of the search state); the human level has them. The attract demo therefore runs with wisps hidden — by design.
- Headless: run the desktop suite WITHOUT `--virtual-time-budget` — everything is stepped synchronously through `__X.freeze` + `step()`, and under virtual time `performance.now()` doesn't advance during JS, so any wall-clock cap in a probe is silently ignored.
- No emoji in the 3×5 font; HUD uses sprites/glyphs only.

## issues
- **Carts must not share sprite names** — `validateCart` rejects a cart whose sprite name already exists in the runtime table (`SPR` is one namespace). Prefix new carts' sprites (`rock_`, `ship`…). The validator is exercised by the desktop probe `validator` (8 negative cases) — keep it passing when the cart contract changes.
- **The belt spawner runs during play tests**: any probe that counts `B.rocks` after several frames must set `B.spawnT=99999` first (it bit `split-large` and `death-respawn` on the first run). `beltStart()` resets `spawnT=30`.
- **Key maps are swapped on insert/eject and `btnState` is cleared** — a key held across a swap is dropped rather than stuck; `blur` also clears. Pad buttons remember which button index they pressed (`held`) so a map swap mid-press releases the right one.
- **Completability is machine-checked** (probe `completable`, Jupiter): a best-first search over the REAL physics (seam `__X.step/press/clearPrev/clearFx`, `noRender`), waypointed through every one-way band + gem in x-order, then the exit. Any Jupiter physics/level change → rerun; the baked demo (`DEMO_RLE`) MUST be regenerated afterwards or `demo-bake` fails (it replays the script and requires clear + 8/8 + 0 deaths).
- Headless: run the desktop suite WITHOUT `--virtual-time-budget` — everything is stepped synchronously through `__X.freeze` + `step()`.
- No emoji in the 3×5 font; HUD uses sprites/glyphs only. Font chars: A-Z 0-9 . : ! - / , ? > × ♥ · ' ( ) space — cart names/tags/boot lines are validated against this set.

# Autotetris — notes

## log
- v1.0 (2026-09-17): Built per three chat requests ("self-playing Tetris spectator with flawless legal piece placement, pause and speed controls, hold and next previews, score, and clean retro/CRT visuals", "…with legal-placement tests, CRT visuals, speed controls, pause support", "prioritize finishing the autonomous Tetris spectator, then run legal-placement and browser checks, keeping all meltdown effects simulated only" — there are no meltdown effects; the only effects are simulated CRT scanlines, glow and a line-clear flash). Existing `tetris` app is a human-played game; this is a spectator. `<script id="eng">` = pure, node-testable: 10×20 (+2 hidden rows), seeded 7-bag, SRS states + JLSTZ/I kick tables, hold (once per piece), 6-deep queue, guideline line scores × level, level = lines/10+1, honest top-out (spawn collision). AI = Dellacherie-style evaluation (aggregate height −0.51, lines +0.76, holes −0.36, bumpiness −0.18, danger penalty near the top) over PLACEMENTS PROVEN REACHABLE: rotations at spawn (cw/ccw chains with kicks) then pure horizontal shifts at that height, each step collision-checked, then drop; hold is considered when it scores better. `execute()` replays the chosen path step by step and REFUSES if any step fails (rotation blocked / shift blocked / target not reached / drop height mismatch) — the UI treats a refusal as a bug and stops. Playback animates the verified path (rotate, shift, fall) at ½× 1× 2× 4× 16×, pause (button/Space/P), new game (button/N), seed shown (?seed= replays), hold + next canvases, score/level/lines/pieces/tetrises/pace/best/games, localStorage best+games, auto-restart after a top-out. Sixtyfour + Azeret Mono, phosphor green on a bezelled CRT.
- Verified: engine 24/24 node (shapes, 7-bag + seeding, spawn, kicks incl. I table, 2-line and tetris scoring with gravity after clears, hold rules, every reachable placement replays legally from spawn, 5 seeds × 400 pieces with ZERO illegal moves / overlaps / floating locks / unreachable paths, survives 400 on every seed, ≥120 lines per 400 pieces, step(), honest top-out, hygiene); browser 32/32 at 1200/390/320 (labels/targets, 40 pieces at 16× with every recorded lock inside the board, HUD = engine, previews painted, coloured board, pause via button/Space/P freezes everything, speed keys, ½× animates instead of teleporting, every animated intermediate state legal on the current board, new game + N key, same seed replays the same 30 placements, persistence); screenshots both widths after a layout fix (board pinned to clamp(200px,42vw,340px), preview canvases capped at 7rem).

## issues
- Layout lesson: `width:100%` on small pixel canvases inside grid columns scales them to the column — cap mini canvases with max-width, and pin the board width instead of letting the columns decide.
- Fixture lesson: a "topped-out" board must NOT consist of full rows — the engine clears them on the next lock and the game happily continues; block the spawn rows with one column open.
- The AI never tucks or spins (by design: only spawn-row rotations + shifts are provable); tetrises are rare with these weights.

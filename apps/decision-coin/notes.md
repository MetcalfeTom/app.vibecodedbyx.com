# Decision Coin — load the odds, flip, obey (or don't)

## log
- 2026-08-28: v1.0 — built per public request ("polished decision coin app with weighted choices, dramatic reveal animation, history, and accessible controls"). OPTIONS: 2–6 options, each with a name (40 chars, placeholder "Option A…") + weight slider 1–10; live % readout per row, `aria-valuetext` "weight 8 of 10, 62% odds", odds line under the list, "fair coin" / "loaded coin" badge, add / remove (min 2, max 6) / even-the-odds, 5 presets (yes-no, heads-tails, dinner 5:4:6, now-later 7:3, work-nap 3:7). Persisted in localStorage `decision-coin-v1` (validated on load). COIN: CSS 3D (`preserve-3d`, backface-hidden faces at ±.45rem, conic-gradient brushed gold + enamel inlay in the option's colour, label + odds on the face). JS-driven flip, H=13 half-turns: `buildSeq` fills a face sequence backwards from the winner with no two adjacent equal; phase 1 (2.2s) rises 150px and spins with outQuart ease to `A_hang = 12*180-120` (runner-up face tilted 60°), phase 2 (0.7s) hangs on the edge with a decaying wobble + "it is hanging on the edge…", phase 3 (0.42s) tips over with outBack onto the winner, squash 6%, flash + 14 sparks. Faces are re-labelled at each half-turn boundary so both sides always show the right thing (front = seq[h+(h%2)], back = seq[h+1-(h%2)]). `done()` re-syncs faces at `A_end` — required, since the last frame can land before the final boundary. Animation loop = rAF with a 50ms setTimeout fallback (`schedule()`), so a backgrounded tab (or headless virtual time) never leaves the coin mid-air. Winner chosen BEFORE the animation via `crypto.getRandomValues` roll → cumulative weights; the roll (3 dp) is shown under the verdict and in every history row, so a loaded coin can't cheat quietly. Reduced motion: crossfade instead of the spin. HISTORY: 60 entries, newest first, colour bar = winner, "of A 33% · B 27% · roll 0.483", obeyed/overruled tag, ↺ reuse (rebuilds weights from stored pcts, max→10), two-tap clear (arms for 4s), stats line with running obey/overrule commentary after 3 verdicts. VERDICT: after a flip, focus lands on "✓ obey"; obey/overrule stamps the latest entry only (`h===S.last`). A11Y: everything is a real button/input, `role=status` announcer for every action, coin is a `<button aria-label="Flip the coin">` with a description, F key flips (ignored inside inputs), 44px targets incl. range inputs, focus-visible cream outline, controls disabled while flipping, reduced-motion path. SOUND: off by default, Web Audio ticks per half-turn + launch noise + hang tone + land thud + win arpeggio, `aria-pressed` toggle, persisted. Fonts: Yeseva One + Sometype Mono; deep-green felt + gold. Probes: desktop 33/33 (boot, idle faces, pcts/pick fixtures, slider aria-valuetext, rename, add/cap/remove, preset, seq invariant ×30, coin geometry 224px + elementFromPoint hit-test, busy state, fast flip → winner == hist == front face == transform 2160°, roll transparency `pick(r)==w`, history row, focus, obey, F-key + F-in-input ignored, overrule/stats, persistence, reuse weights 8/7/10, real-timing drama phases (air → hang → done in ~3.3s), two-step clear, sound toggle, tap targets, a11y attrs, buildstamp, zero errors), mobile 7/7 (no horizontal scroll, coin fits 184px, stacked stage-over-options, hit-test, tap flip, targets, errors).

## issues
- Headless harness: rAF fires ~3 frames per 200ms under `--virtual-time-budget`, so a pure-rAF animation never completes in probes. The app's `schedule()` timer fallback fixed both the probe and the real background-tab case. Keep it.
- Port collisions between parallel jobs are real: check the port right before starting, start `node serve.js &` directly (not `cd && node … &`, or `$!` is the subshell and `kill` misses), and never `pkill -f serve.js` — that kills other jobs' servers.
- Sparks are anchored to `.scene` centre, ~2% above the coin centre; imperceptible, not worth fixing.

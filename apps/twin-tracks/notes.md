# Twin Tracks

Duplicate song finder, asked for by pushedbutton on 2026-09-27 ("dedupe my MP3 files... letting the user verify them by showing matching waveforms"). The flip test is their idea too ("inversion trick: two songs played at the same time sum to silence").

## log
- 2026-09-27 v1.0: pick a folder (webkitdirectory), pick files, or drop a folder (webkitGetAsEntry walk, `_rel` path expando). Everything local; nothing uploaded.
  - Exact copies: same size → SHA-256 → same bytes. Exact families share one decode.
  - Same audio: decode at 8 kHz mono via OfflineAudioContext (decodeAudioData resamples to the context rate = light on memory), 4 one-pole bands (<150, 150–500, 500–1500, >1500 Hz), log energy per 10 ms, floored at max−50 dB, lead-in silence skipped, triangular smoothing then 20 fps, first difference quantised to Int8. Similarity = mean Pearson over the 4 bands, best of ±16 lags (±0.8 s). Only tracks within 6 s duration and a 48-step coarse-shape corr ≥ 0.5 get compared. SAME ≥ 0.80 (union-find), MAYBE 0.62–0.80 (pair cards).
  - Cards: tier badge, every copy's waveform on one shared clock (offsets from the lag), ★ suggested keeper (bitrate, then no "(1)/copy" in the name, then shorter path), Keep/Remove toggles, "Keep ★, mark the rest", "Mark the extra exact copies". Play any copy; switching copies keeps the same moment (A/B).
  - Flip test (non-exact rows vs ★): decode both at 22.05 kHz, align to the sample (8x-decimated search then exact ±12), least-squares gain/polarity, residual energy in dB → silence / whisper (≤−30) / mostly (≤−12) / doesn't cancel. "Hear what's left" plays the first 60 s of the residual.
  - Removal list: Copy list / Save list (.txt, relative paths). Browsers can't delete files; the page says so.
- 2026-09-27 v1.1 (big libraries; pushedbutton started a 9000-song scan on v1.0): v1.0's coarse screen summed the bands, so unrelated fixture songs scored 0.82–0.87 and nearly every pair got the full comparison (hours at 9000). Now: coarse = 48 steps x 4 bands, each band mean-removed (twins 0.81, others ≤0.22; COARSE 0.6), then quickSim = the full comparison on a 20 s middle slice (lofi 0.873, evil twin 0.355; QUICK 0.5), then the full 4-minute one. Duration window uses the length after the lead-in silence (tdur), ±3 s. Worst case (every pair passes the coarse screen) 1500 tracks = 21 s.
- Fixture results (scratchpad tt/mkfx.py: synthetic songs, exact copy, retagged LIST chunk, 11 kHz lofi quieter +0.337 s lead-in + hiss, and an "evil twin" = different song at the same tempo and length): lofi 0.874 (grouped, offset 0.35 s), evil twin 0.389 (not grouped), retagged flip = silence, lofi flip −14 dB. Scan of 9 files 0.2 s.
- 2026-09-27 v1.2 (two sweeps, pushedbutton's idea): **quick sweep** reads no audio: audioSpan() finds the music bytes past the tags (ID3v2 incl. v2.4 footer, ID3v1, APE; FLAC frames after the metadata blocks; WAV data chunk; M4A mdat box; other formats = whole file). Files with the same format + music length get their music bytes hashed (ahash) and their tag bytes hashed (hash = ahash + tag hash). Same ahash = a family: all same hash → "Exact copy", else "Retagged copy" (new tier, ochre, chip "Retagged"). Cards lazily decode one file per family when scrolled into view (serial lazyQ) to fill in waveform, kbps and duration. **Deep listen ☕** button = the old decode + fingerprint + match, one decode per family, with an ETA; families stay one node, so quick-sweep sets survive and merge into "Same audio" sets. Stopping partway keeps the box as "Keep listening" (fps persist on items). Marks now live on the item (it.gone), so they survive the deep listen. Fixtures: scratchpad tt/mkfx2.py adds fake-music MP3s with ID3v2/APE/ID3v1 layouts and M4As with different moov (they can't decode, so they also show the "can't draw this one" path).
- 2026-09-27 v1.3: fingerprints are remembered in IndexedDB ('twin-tracks' db, store 'fp', key = FPV|path|size|lastModified, one entry per family member, written in batches of 25). Deep listen loads remembered ones first ("N remembered · Listening to…"), so a reload + rescan of a big library only decodes new or changed files; quick-sweep cards check memory before decoding. Hero shows "I remember N songs… Forget them" when there are any. Failed decodes are not remembered (they retry). Bump FPV whenever fingerprint() changes. Fixture test: 2nd scan decoded 0 of the 4 decodable families.
- 2026-09-27 v1.4: the bulk button follows the filter: All = "Mark the extras in N byte-proven sets" (exact + retagged only), Exact/Retagged/Same = that tier's sets, Maybe = hidden (always one by one). Marks sync across cards holding the same file (a file can be in a Same set and a Maybe pair). Cards only repaint once they've been scrolled into view (el._seen), so a bulk mark doesn't queue a decode for every quick-sweep card.
- 2026-09-27 v1.5 (pushedbutton found 8 GB of duplicates in their real library; a cleanup that size spans visits): Remove marks persist in localStorage `twin-tracks.marks` = {path|size: 1}. applyMarks() runs in renderResults before drawGroups and only touches rows it hasn't seen yet (`it._mk`), so an unmark this session sticks; saveMarks() (300 ms debounce, from updateDock when groups exist) writes set/delete for every row in a set and leaves other folders' marks alone. Toast "N files are still marked from last time"; hero note with Clear marks. Probe scratchpad gaunt/sw/tt/v15.html#marks: save → rescan restores → unmark → bulk → clear → fresh scan all pass, 0 errors.
- 2026-09-27 v1.6 (pushedbutton wrote their own batch file to clear 8 GB, and offered to test a quarantine): **Move script** button in the dock saves twin-tracks-move.bat on Windows (navigator.platform) or twin-tracks-move.sh elsewhere. It MOVES the marked files into `_twin-tracks-removed/` mirroring the folder structure; nothing is deleted, missing files print "not found", reruns are harmless. Paths: if every marked path shares one top folder (the scanned folder name from webkitRelativePath / drop fullPath) it is stripped and the script goes inside that folder; otherwise it keeps full paths and goes next to them. Single-file picks (no '/') get a toast instead. .bat: chcp 65001, cd /d %~dp0, % doubled, every name quoted (parens and & stay literal inside quotes), CRLF. .sh: single-quoted with '\'' escaping, mv -n. The .sh ran on a copy of the fixtures (5 moved, second run 0 moved + not-found lines); the .bat is untested on real Windows so far (pushedbutton offered).

## issues
- Fingerprints only cover the first 4 minutes (MAX_FRAMES); a radio edit vs album version with the same start can land in "same audio" if the durations are within 6 s. The flip test and ears are the safety net.
- Decoding big libraries is the slow part (2 files at a time), so it's the opt-in deep listen now. Stop shows what was found so far; Keep listening resumes.
- The harmony-mixer lesson applies: a coarse "same track?" fingerprint false-positives as a deletion test. Keep the evil-twin fixture in any change to the matcher.

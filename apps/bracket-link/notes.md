# Bracket Link

Tatum's idea (2026-10-02): a tournament bracket for an online group, no accounts.

## How it works
- The whole bracket (title, names, winners, id) is base64url JSON in the URL hash: `#b=` organizer copy, `#view=` look-only copy. Since v2.0 slip codes go to a database (table `bracket_link_slips`); since v2.1 the organizer's look-only sheet does too (table `bracket_link_sheets`, title + names + results, never the key), once that organizer has handed out a link carrying their user id.
- localStorage `bracket-link-v1` keeps the organizer's last bracket; a link in the address bar wins over it.
- Single elimination, size = next power of 2, standard seeding (1 v 16, 8 v 9...), byes go to the top seeds and auto-advance.
- Winners stored per match id as a player index; layout() drops any stored winner that is no longer in its match, so undoing an early result unravels the later rounds.
- Same number of names = rename, results kept. Different count or shuffle = restart (with a confirm strip).
- Test hook: `window.__BL` (S, layout, enc, dec, clean, render, link, view). S.o (v2.1) = the organizer's Supabase user id, uuid bytes as 22 base64url chars, kept by clean().

## Look
Paper sheet taped to a pub wall: #f2eee3 paper, ink #15120e, one red marker #d7342a, gold champion. Big Shoulders Display + Spline Sans Mono.

## Issues
- Tatum wants players to report results themselves and the organizer to settle disputes, ideally with a database. Built in v2.0 with one Supabase table: visitors add and read rows, never names or brackets, only the slip code.
- v2.0 table as built: the create-table tool's default policies also let a user update/delete their OWN rows (unused by the app) and it can't add a size CHECK. The app caps codes at 400 chars on both sides, but the DB itself doesn't. Accepted as is: a slip row is a short code string, junk is ignored and rows are capped per pull.
- Anyone with the share link knows the bracket id and could insert junk or unsigned slips for it. Junk is ignored (not a BL- code for this id), unsigned slips still ask add it / ignore, caps: 80 rows per user per pull, queue of 60. Signed slips can't be forged without the personal link.
- The organizer copy only sees slips while it is open (it catches up on open). The 15-min quiet rule still starts when a slip ARRIVES at the organizer's copy, not when it was sent.
- #view copies and players never read the slips table; only a copy with the key does. Since v2.1 #view copies with an o read `bracket_link_sheets` (only the organizer's rows).
- v2.1 privacy: the sheet (title, player names, results, slip states) is now stored online and readable by anyone who knows or guesses the bracket id (6 chars), like everything in these tables. The key k never goes in. Said plainly at the auto toggle; turning auto off deletes the organizer's row (needs a connection at that moment, otherwise it stays).
- v2.1 trust rule: a player's copy only accepts rows whose user_id equals the o in the link the player opened. The create-table tool's default policies are INSERT WITH CHECK (user_id = auth.uid()), UPDATE USING (auth.uid() = user_id) (no separate WITH CHECK, so Postgres uses USING for the new row too), DELETE USING (auth.uid() = user_id): nobody can write a row in someone else's name. Anyone can still write rows in their OWN name for any bracket id; players ignore those (query filters user_id = o, checked again client side).
- v2.1 limits: o is per sign-in. An organizer on a second device (organizer link) publishes under their own id and their new share links carry it; players on the first device's links keep following the first device. A cleared cookie / new anonymous sign-in = new o: old links stop following, new links work. Links shared before v2.1 have no o and never follow (the next shared link fixes it). No size CHECK in the DB (app caps 20000 chars both sides). updated_at isn't maintained by a trigger (the app doesn't use it).
- v2.1 first share click with NO existing sign-in waits for an anonymous sign-in before copying; on iPhone Safari the clipboard may refuse after the wait, then the link shows in the box up top to copy by hand.
